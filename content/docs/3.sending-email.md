---
title: Sending email
description: Use the HTTP API with bounded content attachments and an authorized sender.
---

## Request

```bash
curl -X POST https://email.example.com/send \
  -H "Authorization: Bearer $EMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "to": "recipient@example.net",
    "subject": "Welcome",
    "text": "Your account is ready."
  }'
```

The optional `from` address must be either the API key owner or the active provider's default sender. Recipient addresses are syntax-validated. Subjects cannot contain header control characters.

## HTML

Send either `text` or `html`. Keep each body below 1 MB. Sanitize untrusted values before inserting them into HTML.

## Attachments

Attachments accept inline `content` only. Local paths and URLs are intentionally unsupported.

```json
{
  "filename": "report.pdf",
  "content": "JVBERi0xLjQK...",
  "encoding": "base64",
  "contentType": "application/pdf"
}
```

Limits are 10 attachments, 10 MB per attachment, and 15 MB total decoded attachment data.

## Responses

- `200`: queued successfully.
- `400`: invalid or oversized request.
- `401`: missing, invalid, or revoked API key.
- `403`: sender is outside the key's allowed identity.
- `429`: rate limit exceeded.
- `503`: no outbound provider is active.
