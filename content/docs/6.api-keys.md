---
title: API keys
description: Issue, store, rotate, and revoke sending credentials.
---

## Key ownership

Members see and revoke only keys issued to their own dashboard email. Administrators can manage all keys. Raw keys are emailed once; the service stores only a SHA-256 hash and a display prefix.

## Storage

- Use a secret manager or encrypted CI variable.
- Never put a key in source control, a URL, browser storage, or screenshots.
- Send keys only as `Authorization: Bearer <key>`.
- Create separate keys for separate applications.

## Rotation

Request a replacement, deploy it to the client, verify delivery, then revoke the old key. Revocation takes effect on the next API request.

## Suspected exposure

Revoke the key immediately, inspect recent email activity, rotate downstream credentials if message contents contained secrets, and notify an administrator.
