---
title: Operations and security
description: Monitor delivery, protect secrets, and respond to failures or suspected compromise.
---

## Daily checks

- Review failed and delayed queue counts.
- Investigate provider authentication failures.
- Confirm inbound polling success and webhook retry levels.
- Remove unused API keys and members.

## Required secrets

Infrastructure administrators manage `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, `SETTINGS_ENCRYPTION_KEY`, and `INBOUND_CONFIG_ENCRYPTION_KEY`. Use independent, high-entropy values. Back up encryption keys securely; losing one makes encrypted settings unreadable.

## Safe logging

Do not log API keys, login codes, provider credentials, webhook secrets, authorization headers, full inbound MIME, or attachment bodies. Provider errors shown to public callers are intentionally generic.

## Incident response

1. Revoke affected API keys and dashboard access.
2. Rotate provider or webhook credentials through the dashboard.
3. Preserve relevant audit events and delivery metadata.
4. Determine whether message bodies or inbound MIME were exposed.
5. Rotate encryption keys only with a planned data re-encryption procedure.

## Backups

Back up PostgreSQL and required encryption keys separately. Test restoration in an isolated environment without sending live email or invoking production webhooks.
